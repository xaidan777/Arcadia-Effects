# AFX UI: панели, виджеты, таймлайн

## Событийная шина (AFX.on / AFX.emit)

| Событие | Когда | Кто слушает |
|---|---|---|
| `doc` | загружен/заменён документ | все панели (полный ребилд) |
| `layers` | список слоёв изменился | timeline, inspector (валидация sel) |
| `layer` (id) | параметры слоя изменились | timeline (queueRebuild), preview, inspector (обновить значения) |
| `comp` | глобальные настройки (touchAll) | preview, timeline |
| `select` | выделение слоёв | timeline, inspector |
| `time` | время изменилось | preview, timeline (playhead), инспекторские updaters |
| `dirty` | флаг несохранённости | catalog (точки), кнопка Save |
| `tex` | реестр текстур | textures, globals |
| `atlas` | настройки экспорта | preview (atlasDirty) |
| `play`, `tab`, `tlmode`, `keysel`, `resize`, `gizmos`, `forces` | локальные |

Правило: панель ребилдится по событиям, НЕ мутирует чужое состояние напрямую.

## Undo-протокол (везде одинаковый)

- Дискретное действие: `AFX.pushUndo()` -> мутация -> `AFX.touch(layerId)` ->
  `AFX.commitEnd()`.
- Драг: undo пушится ОДИН раз на флаге первого move (`if (!started) { started
  = true; AFX.pushUndo(); }`), мутация+touch на каждый move, commitEnd на up.
- `pushUndo` сам ставит dirty и эмитит 'dirty'. Не звать pushUndo без мутации.

## Таймлайн (timeline.js) — критические места

- **interacting-флаг**: ЛЮБОЙ pointer-драг внутри таймлайна (бары, края, ключи,
  стопы градиента, график) обязан вызывать `beginInteract()` в start и
  `endInteract()` в end. Иначе `queueRebuild` пересоздаст DOM/канвас посреди
  драга и координаты "сорвутся" (реальный старый баг). rebuild откладывается
  во `pendingRebuild` и выполняется на endInteract.
- **timeMin**: шкала может уходить в минус (пре-ролл, отрицательный layer.start).
  Все маппинги только через `xOf(t)` / `tOf(x)`. Время ключей клампится >= 0
  (`snapKey`), старты баров — НЕ клампятся (`snapTime`).
- **Живые обновления при мультидраге**: rebuild подавлен, поэтому позиции
  двигаемых элементов обновляются вручную через `keyElMap` (key -> el) и
  `barPlaceMap` (layerId -> placeFn). Новые draggable-элементы — регистрируй там же.
- Выделение слоёв: `AFX.Ops.selectOnly/selectToggle` (Shift/Ctrl = toggle).
  Primary = `state.sel`, множественное = `state.selLayers` (Set). Драг бара
  двигает ВСЁ выделение одним снэпнутым смещением.
- Ключи: `state.selKeys` = [{layerId, path, tr, key}] — ссылки на живые объекты;
  после undo/loadDoc выделение сбрасывается (объекты заменены). `AFX.deleteSelKeys`
  (app.js) при опустошении трека возвращает СТАТИКУ по тому же пути — резолвить путь
  обязан ЦЕЛИКОМ (было: первые два сегмента, и 'em.path.nodes.0.x' затирал em.x).
- **Пан средней кнопкой**: СКМ-драг по листу двигает `scrollLeft/scrollTop`; в режиме
  графика драг перехватывает канвас — X скроллит время, Y сдвигает `graphPan` (ось
  значений, единицы свойства; входит в `graphRange`), клик СКМ без движения возвращает
  автофит. `graphPan` сбрасывается при смене цели графика (`syncGraphPan` по подписи
  `layerId|path|curve`, зовётся из `drawGraph`), у кривой за жизнь вертикали нет (ось
  фиксирована 0..yMax). Документ пан НЕ мутирует — pushUndo не звать, но
  beginInteract/endInteract обязательны. `mousedown` с button 1 гасится на `#timeline`,
  иначе Chrome включит autoscroll. Скраб линейки — только button 0.
- **Шпаргалка хоткеев** (`#tl-hints`): полупрозрачный оверлей в углу листа,
  `pointer-events:none`, состав берётся из таблицы `HINTS` по режиму и обновляется по
  событию `tlmode`. Клавиша и действие — отдельные английские строки через `L()`
  (RU-словарь: 'MMB drag' -> 'СКМ драг' и т.п.). Новый хоткей — строка в `HINTS`.
- График: три режима цели (`getGraphTarget`): числовой трек (ключи+безье-ручки),
  кривая за жизнь (kind:'curve', ось X = 0..1 через cToX/xToC), цветовые треки
  в график не пускаем. `graphView` замораживает диапазон значений на время драга
  (иначе автофит создаёт петлю обратной связи).
- ДИНАМИЧЕСКИЕ свойства: `PROP_PATHS` статичен, но у эмиттера к нему добавляется
  `pathPropPaths(layer)` — узлы пути (`em.path.nodes.<i>.x/y`) плюс jitter/attract/
  lock/flow. Лейблы таких путей строит `propLabel()` (регэксп по индексу узла),
  и он же используется в `getGraphTarget` — не возвращай туда `PROP_LABELS[path]`.
- Строки кривых/градиента (ol-rows) — только у эмиттеров; полоса растянута на
  0..dur И ПРЕДСТАВЛЯЕТ жизнь 0..1 (не время композиции!) — не "чинить".
- **МАРКЕРЫ КАДРОВ АТЛАСА** (`buildFrameMarkers`, только при `state.tab === 'atlas'`):
  голубые флажки в `#tl-ruler` — это ГРАНИЦЫ кадров (`Atlas.frameTimes().bounds`,
  frames+1 штук), а не их сэмплы. Первый = `exp.t0` (поле Start), полый последний =
  `exp.t1` (End), внутренние = `exp.cuts` долями. Драг: `beginInteract` -> pushUndo
  на первом move -> мутация `doc.exp` -> `placeAll()` (ребилд подавлен, позиции
  двигаем руками — драг края двигает ВСЕ внутренние маркеры, они доли диапазона) ->
  `AFX.setTime` на центр редактируемого кадра -> на up `emit('atlas')` + commitEnd.
  `emit('atlas')` ТОЛЬКО на конце драга: он пересобирает лист атласа, на каждый move
  это неподъёмно. Собственный `D.drag` маркера гасит pointerdown линейки (скраб).
  Таймлайн подписан на `tab` и `atlas` — без этого маркеры не появятся/не поедут.

## Виджеты (widgets.js)

- `W.num` с `track:{layer,obj,key}` = анимируемый параметр: секундомер
  включает/выключает трек, правка значения при включённом треке ставит ключ
  в текущем времени (автокей через `snapLocal`, снэп по fps). Ромб — ключ вручную.
- `reg` — массив рефрешеров: инспектор дёргает их на 'time'/'layer', чтобы
  показывать анимированные значения. Новые виджеты с зависимостью от времени —
  регистрируй туда же.
- Пикер спрайтов строит параметры по `shapeDefs[].params` автоматически;
  после смены параметров фигуры звать `S.clearShapeCache('shape|'+id)`.

## Подсказки при наведении (dom.js: `D.tip`) — ОБЯЗАТЕЛЬНЫ

- У КАЖДОЙ настройки и кнопки есть подсказка: что контрол делает, а не его имя.
  Текст — английский через `L()`, перевод — в словаре `TIPS` (i18n.js, не в RU),
  **30–120 символов И по-английски, И по-русски**. Проверка: `node tools/i18ncheck.mjs`.
- Как повесить (checker видит ТОЛЬКО эти формы — позиционный аргумент хелпера он
  пропустит, так уже терялись кнопки транспорта и поля диалога секвенции):
  - `h(tag, { tip: L('...'), tipHead: name })` — атрибуты `data-tip` / `data-tip-head`;
  - `D.tip(el, L('...'), head)` — текст ВТОРЫМ аргументом, возвращает el (можно оборачивать
    `D.tip(field(...), L('...'))`);
  - виджеты `W.*({ ..., tip: L('...') })`; кнопки модалки — `D.modal({ acceptTip, cancelTip })`;
  - данные: `tip: '...'` рядом с `label` (фигуры `S.shapeDefs` и их params) или таблица `NAME_TIPS = {}`.
- `W.row(label, tip)` вешает подсказку на ВСЮ строку (лейбл + поле), шапка — полное имя
  параметра (узкий лейбл обрезается, особенно по-русски). Свои подсказки дочерних
  кнопок (секундомер, ромб ключа) перекрывают строку: побеждает ближайший владелец.
- `tipHead` — данные (имя слоя/эффекта/текстуры, значение ключа), `tip` — объяснение.
  Имена не оборачивать в L(), подсказку без объяснения не делать.
- Пустой `data-tip` глушит подсказку предка (маркеры кадров на линейке: у них своя
  CSS-подсказка `.fm-tip`). Нативный `title` не использовать — движок перехватит его и
  покажет своим тултипом, но checker такой текст не проверит.
- Поведение движка: один `.afx-tip` на документ, делегированный `pointerover` (ребилды
  панелей бесплатны), задержка 420 мс, «тёплый» режим 500 мс (соседние всплывают сразу).
  Нажатие / клавиша / колесо прячут и ДЕРЖАТ подсказки, пока курсор не сдвинется на 6 px:
  после драга бара или Ctrl+Z панель пересобирается, и новый элемент под неподвижным
  курсором получает pointerover — без удержания подсказка всплывала сама. Во время драга
  (`e.buttons`) не показываются. Владелец ушёл из DOM — подсказка гаснет (опрос 250 мс).
- Покрытие всех состояний UI проверялось headless-аудитом: интерактивный элемент без
  владельца `data-tip` = ошибка. Новый виджет/кнопка без подсказки — регресс.

## Типы слоёв в UI

- Таймлайн строит строки свойств из `PROP_PATHS[layer.type]` — новый тип слоя без
  записи в эту таблицу молча остаётся без анимируемых свойств. Там же бейдж
  (E/S/A) и класс бара (`.tl-bar.<type>` в CSS).
- Бейдж строит `TYPE_BADGE` (E/S/A/F/FF, экспортируется в `AFX.Timeline.TYPE_BADGE` —
  им же подписывает адресатов виджет `W.targets`), подпись бара — по типу; у POSTFX-слоя
  `opacity` подписан «Effect strength» (это сила эффекта, а не прозрачность) —
  и в инспекторе, и в `propLabel(path, layer)` таймлайна.
- Гизмо превью: владельца центра отдаёт `centerOwner(layer)`. У POSTFX центр есть
  ТОЛЬКО в режиме radial (это центр смаза), в directional центра нет и `g.center`
  равен null — все потребители обязаны это переживать. У FORCE-слоя центра слоя нет
  вовсе: центры свои у каждого поля (`g.ff`, хит `kind:'ffield'` с индексом поля,
  приоритет выше затухания и центра; цвет по виду поля — `FF_COL`).
- ДИНАМИЧЕСКИЕ свойства есть и у FORCE-слоя: `forcePropPaths(layer)` даёт
  `ff.fields.<i>.strength|x|y|sx|sy`, лейблы — тот же `propLabel()` (регэксп по индексу поля).
- АДРЕСАЦИЯ корректоров — виджет `W.targets({layer, kinds, onToggleEmpty})`: чекбоксы
  слоёв НИЖЕ по стеку, пусто = «всё, что ниже». Переход «пусто <-> есть адресаты»
  меняет состав секции (у postfx появляется «Group blend»), поэтому виджет зовёт
  `onToggleEmpty` -> `Insp.rebuild()`, а не свой локальный ребилд.
- ПИКСЕЛЬ-АРТ (`buildPixelate`): секции Pixel grid / Sampling / Color quantize /
  Outline / Export. Читалка сетки (`.px-info`) считается из `Model.pixelGridOf` и
  регистрируется в `reg` — она обязана обновляться при правке разрешения и снапа,
  иначе артист не увидит, что блок стал дробным (оранжевый «uneven blocks»). Галочка
  `Pixel art 1:1` продублирована в инспекторе и в Atlas Export — это ОДНО поле
  `doc.exp.pixelArt`, обе точки эмитят `atlas`. В глобальной панели при включённой
  галочке Cell W/H и Supersample не показываются вовсе: они ничего не решают.
- Инспектор диспетчеризуется по `layer.type` (buildEmitter / buildAtlas / buildPostFx / buildForce / buildSprite).
  Для ATLAS-слоя пикер спрайта зовётся с `texOnly: true` (без секции фигур,
  с кнопкой импорта листа), мёртвые для текстур регуляторы (тонировка, свечение
  спрайта) не показываются — их нет и в PROP_PATHS.atlas.

## Модальные диалоги (dom.js)

- `D.modal({title, body, wide, acceptLabel, cancelLabel, acceptTip, cancelTip, onAccept, onCancel})` —
  оверлей + бокс + пара кнопок (`*Tip` — подсказки кнопок, см. раздел о подсказках). Esc = отмена, Enter = принять, клик по фону = отмена;
  `onAccept` может вернуть `false`, чтобы не закрывать (валидация).
- Пока модалка открыта, глобальные горячие клавиши отключены целиком
  (`AFX.Dom.modalOpen()` — ранний return в keydown app.js). Поля ввода в модалках
  делать `type="text"`: числовые input в app.js не считаются текстовым вводом.
- Диалог атласа: `TP.openAtlasPicker({accept(texId)})` — источник (файл / drop-зона /
  лист проекта) + `buildGridEditor`; кнопка Accept заблокирована, пока источника нет
  (`D.modal` отдаёт `acceptBtn`). Своя drop-зона обязана гасить событие
  (`stopPropagation`), а глобальный импорт файлов — молчать при `D.modalOpen()`,
  иначе один брошенный PNG уедет ДВАЖДЫ: и в диалог, и в текстуры.
- Диалог секвенции (`GlobalsPanel.openSequenceDialog`, кнопка в топбаре) не мутирует
  док ВООБЩЕ: экспорт — это вывод, его настройки живут в модульной переменной (на сессию).
  Поэтому в нём СВОИ поля ввода, а не виджеты `W.*` — те зовут `pushUndo` и пачкают dirty.
  Долгий экспорт идёт ВНУТРИ открытой модалки: `onAccept` возвращает false (не закрывать),
  прогресс рисуется в теле, Cancel зовёт `job.cancel()`.
- Мутация документа — ТОЛЬКО в `onAccept` (по undo-протоколу); открытие диалога
  и правка его полей ничего в доке не трогают, иначе «Отмена» будет лживой.
- Пример: диалог сетки спрайт-атласа `AFX.TexturesPanel.openSheetDialog`
  (сетка предлагается по соотношению сторон: `baseGrid`/`gridFamily`/`guessSheet`).

## Инспектор / глобальные

- Секции блока частицы (`particleSection` / `rotationSection` / `physicsSection` /
  `appearanceSection`) параметризованы объектом `pt` и строятся ДВАЖДЫ: для
  `layer.pt` и для `em.sub.pt` (суб-эмиттер). Новый параметр частицы добавляется
  в них ОДИН раз и автоматически появляется у дочерней частицы — не разводить
  две копии виджетов. Кривые/градиент СУБ-частицы правятся только в инспекторе:
  строки ol-rows таймлайна и `getGraphTarget` завязаны на `layer.pt`.
- Пути свойств таймлайна (`PROP_PATHS`) — любой глубины (`em.sub.pt.size`),
  `resolve()` идёт по всем сегментам.
- Инспектор строится схемой «секция -> виджеты» в buildEmitter/buildSprite.
  Новый параметр слоя = поле в фабрике модели + миграция + виджет здесь
  (+ строка в таймлайн PROP_LABELS/PROP_PATHS, если параметр анимируемый).
- Лейблы — английские в коде + `L()` + перевод в i18n.js (см. workspace-скилл).
- Поля экспорта Start/End правятся ДВУМЯ точками (панель и маркеры таймлайна),
  поэтому globalspanel держит `expReg` — массив рефрешеров `W.num`, дёргаемый по
  событию `atlas`. Полный `G.rebuild()` на это событие вешать НЕЛЬЗЯ: он уничтожит
  виджет под курсором посреди чужого драга.

## Плеебл-вьюпорт вкладки атласа (preview.js)

- Панель `#atlas-play` справа от `#preview-view` внутри `#preview-area` (flex-строка),
  своя ширина `--apw` + сплиттер `data-split="ap"`; и панель, и сплиттер живут только
  на вкладке atlas (`syncAtlasPlay`). Смена вкладки МЕНЯЕТ ширину вьюпорта — обработчик
  `tab` обязан звать `resize()` до `P.fit()`, иначе вписывание уедет.
- Кадр берётся ИЗ ГОТОВОГО ЛИСТА (`atlasResult`, `drawAtlasTab` собирает его прямо
  перед `drawAtlasPlay`): ячейки уже отрисованы, плейбек не гонит симуляцию и стоит
  одного `drawImage`. Не заводить второй Engine ради «живого» кадра — это и есть
  потеря fps, от которой уходили.
- Плейбек на вкладке atlas — СВОЯ ветка в `loop()` (`playAtlasFrames`): идут только
  кадры листа, `state.time` ставится в ЦЕНТР кадра (плейхед идёт по маркерам), лист
  от времени не зависит и не пересобирается. Темп — поле fps панели (пусто = 0 =
  собственный fps атласа); это настройка ВЬЮПОРТА, в документ не пишется.
- Зум/пан панели — свои (`apZoom/apPanX/apPanY/apFitMode`, координаты через `apBack`),
  правила те же, что у превью: колесо — к курсору, драг ЛКМ/СКМ — пан, дабл-клик и
  кнопка Fit — вписать. `apFitMode` пересчитывает вписывание КАЖДЫЙ кадр, поэтому
  ресайз панели и смена размера ячейки подхватываются сами.
- `P._dbg().atlasPlay.step(dt)` — синхронный прогон кадров для тестов: в скрытой
  вкладке rAF не тикает и плейбек иначе не проверить.
- ЯЧЕЙКИ ЛИСТА интерактивны (`atlasCellAt` / `setAtlasHover` / `selectAtlasCell`):
  наведение — рамка ячейки (золотая; текущий кадр рисуется поверх голубым) плюс
  номер кадра в `#preview-hud`, клик — `setTime` на сэмпл кадра. Хит-тест идёт в тех
  же координатах, в которых лист и рисуется: `(m - pan) / zoom`, без компрессии
  камеры (лист — не композиция). Выбор висит на `end` драга при `moved === false`,
  поэтому пан листа его не задевает; дабл-клик по ячейке НЕ вписывает вид.
  «Выделенность» кадра — это `state.time`, отдельного состояния нет: отсюда и
  подсветка полосы кадра на линейке таймлайна (`drawRuler`, только вкладка atlas).

## Превью (preview.js) и гизмо

### Система координат — нужна ЛЮБОЙ отрисовке и хит-тесту в превью

Три преобразования, все на уровне модуля. Сырые `clientX/Y` с pan/zoom не смешивать.

```
w, h = doc.comp.w / doc.comp.h                 размер композиции
k  = AFX.Model.compK(doc) = cos(cam.comp)     компрессия камеры по Y
kf = viewCanvas.width / rect.width            dpr-масштаб канвы

client -> бэкинг:  toBack(e)   = [(e.clientX - r.left)*kf, (e.clientY - r.top)*kf]
бэкинг -> мир:     worldOf()   = [(mx - panX)/zoom - w/2, ((my - panY)/zoom - h/2)/k]
мир -> бэкинг:     view(wx,wy) = [panX + (w/2 + wx)*zoom, panY + (h/2 + wy*k)*zoom]
```

- Y сжат камерой ТОЛЬКО на экране: в мир идёт делением на `k`, из мира — умножением.
  Мировая дельта из экранной — `[dx*kf/zoom, dy*kf/(zoom*k)]`, экранный вектор из
  мирового — `[fx, fy*k]` (направление стрелки поля сил считается именно так).
- Рамка композиции В МИРОВЫХ координатах: `x ∈ ±w/2`, `y ∈ ±h/(2k)` — НЕ `±h/2`.
  Отсюда берутся границы любых сеток и оверлеев, обрезаемых по кадру.
- Шаг, постоянный на ЭКРАНЕ, в мире равен `S*dpr/zoom` по X и `S*dpr/(zoom*k)` по Y;
  привязка узлов к кратным этого шага мировым координатам = сетка не плывёт при пане.

- Гизмо выбранного слоя: крест-центр (em.x/em.y или sp.x/sp.y) и, при fadeOn,
  оранжевый эллипс затухания с квадратом-центром (fadeX/fadeY). ЛКМ-драг по
  хендлу двигает центр С АВТОКЕЕМ (setTrkVal: трек -> ключ в snapLocalP, статика
  -> напрямую), пустое место — пан. Хит-тест fade-хендла приоритетнее центра.
  Undo: pushUndo на первом move, commitEnd на up. Тумблер Gizmos в тулбаре.
  Координаты — блок выше; драг двигает центр мировой дельтой из экранной.


- ПУТЬ ДВИЖЕНИЯ (`em.path.on`): в превью рисуется фиолетовая линия запечённого пути
  и квадраты-узлы. Драг узла = автокей его треков x/y (тот же `setTrkVal`),
  хит-тест узлов ПРИОРИТЕТНЕЕ затухания и центра. Alt+клик по линии вставляет узел
  в нужный пролёт (`nearest().seg + 1`, undo пушится внутри, драг продолжает тащить
  новый узел). Мировые координаты из экранных — `worldOf()` (y делится на
  компрессию). Буфер запекания пути у панели СВОЙ (`pathBake`), с симуляцией не шарится.
- ДАБЛ-КЛИК в превью — цепочка приоритетов: узел -> удалить (минимум 2 узла);
  ЛЮБОЙ другой хит гизмо (центр, затухание) -> ничего (иначе «вписать» дёргало бы
  вид при попытке попасть по контроллеру); линия пути -> вставить узел; пусто ->
  прежнее `P.fit()`. Центр эмиттера перекрывает линию — это осознанно.
- ПКМ в превью — `previewCtxMenu` (`D.ctxMenu`): пункты зависят от хита (узел /
  линия / слой), плюс общие «Fit» и «Gizmos». Все мутации идут через `pathEdit()`
  (pushUndo -> мутация -> touch -> commitEnd -> `Inspector.rebuild`).
  Тумблер гизмо теперь эмитит локальное событие `gizmos` — кнопка тулбара
  подписана на него, чтобы состояние из меню и из кнопки не разъезжалось.
- `toBack(e)` (client -> пиксели бэкинга) живёт на УРОВНЕ МОДУЛЯ, а не внутри
  `P.init`: им пользуются и обработчики init, и контекстное меню.
- Координаты мыши переводить в пиксели БЭКИНГА канвы через `toBack(e)`
  (dpr-масштаб) — сырые clientX/Y с pan/zoom не смешивать.
- Цикл на rAF: рендер только при playing или needsRedraw. В СКРЫТОЙ вкладке
  rAF не тикает — обход: `P.renderNow(t)` (синхронный draw, ставит время,
  на вкладке atlas пересобирает атлас); см. тест-рецепт в workspace-скилле.
- Приём drag-текстур (`text/afx-tex`) создаёт спрайт-слой в точке броска;
  y делится на компрессию (бросок = экранная точка).
- ПОЛЕ СИЛ (кнопка Forces рядом с Gizmos, тот же тумблер в ПКМ-меню, событие
  `forces`): сетка зелёных стрелок — ускорение, которое почувствует ПОКОЯЩАЯСЯ
  (v=0) частица выбранного ЭМИТТЕРА в этой точке. Слагаемые повторяют sim.js:
  гравитация, curl-поле (`turbAmp`), ветер через сопротивление (`drag*turbWind`,
  при drag=0 ветер ускорения не даёт — ровно как в симуляции), пружина `attract`
  и `flow` вдоль касательной (темп `FLOW_K/DT` = 8/с). Шумовая турбулентность
  ('noise') поля НЕ образует — она своя у каждой частицы (аргументы: возраст и
  seed), легенда пишет про это прямо. Шаг сетки постоянен на ЭКРАНЕ, узлы привязаны
  к мировым координатам (при пане не плывут), длина стрелки нормирована максимумом
  ПО КАДРУ. Буфер запекания пути СВОЙ (`forceBake`) — с гизмо не шарится.
  СИЛОВЫЕ ПОЛЯ слоёв `force` тоже входят в сумму (`ffUnpack`/`ffAccum` повторяют
  `Sim.forceStep`); выбран сам слой-поле — `forceOnlyInfo` рисует ровно его поля,
  без физики какого-либо эмиттера. Сетка узлов у обеих веток одна — `forceGrid`. Оверлей
  ничего не мутирует: ни undo, ни dirty; `forcesOn` в доке не хранится. Легенда
  рисуется СВЕРХУ слева — снизу слева живёт `#preview-hud`.
